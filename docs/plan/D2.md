# D2. Tool calls the permission layer allows, and the builder context counted

- Status: planned
- Records: none
- CI: on
- Branch: `claude/project-thread-5ayzcx`
- Release: patch

The D1 run found three problems. The permission layer refused tool calls that the skills and agents had asked for or invited. The step builder had a ~21 KB skill listing it never needed. The gate-runner polled a background gate with `until`, `grep` and `sleep`. After this lane, every command the skills, agents and plan template give is one plain command per Bash call, and files are written with Write, changed with Edit and searched with Grep. The builder loses the Skill tool and reads its conventions skills from the paths `slipway lane --step` prints. The gate-runner always runs in the foreground. This ship tags `v0.2.1`.

## Constraints

- The run commands are `slipway run <name>`, and a step is one commit whose body carries the trailers ([0001](../adr/0001-the-process.md)).
- `agents/step-builder.md` stays at or under its 4,096-byte ceiling (design §4.4, §7). It gets there by trimming its text; the ceiling in `scripts/components.test.mjs` does not rise.
- `${CLAUDE_PLUGIN_ROOT}` and `$ARGUMENTS` in a skill are substituted by Claude Code before the model reads them, so they are not shell constructs.
- The design keeps its section numbers, because `site/scripts/sync.mjs` reads them and fails the site build on a missing one.

## Steps

### 1. One plain command per call in the skills, agents and plan template

- [ ] Built
- Done when: `slipway run step-check` is green, with `skill, agent and template code spans are plain commands (D2)` passing.
- Records: none
- Paths: `skills/**`, `agents/**`, `templates/plan.md`, `scripts/components.test.mjs`, `CHANGELOG.md`

What this step changes:
- **The test.** A new test in `scripts/components.test.mjs` checks the inline and fenced code in every skill, every agent and `templates/plan.md`. It fails on command substitution, parameter expansion, pipes, `&&`, `||`, `;`, redirects, `!` negation, grouping and `sed -i`. Each failure names the file and the span. `${CLAUDE_PLUGIN_ROOT}` and `$ARGUMENTS` are allowed, and so is a `|` inside a quoted argument-hint.
- **Ship step 8.** Ship reads `git rev-parse origin/<default>` as its own call right after the merge and passes the hash to `--commit`.
- **The agents' rule.** Wherever an agent runs commands, its body says to use one plain command per Bash call, to write files with Write, change them with Edit and search with Grep, and never to use `sed -i` or `echo` with redirects.
- **Done-whens.** The scope skill and `templates/plan.md` say a done-when is a plain command or a test name. A negative check, such as "no file says X", becomes a test.
- **Changelog.** `## Unreleased` gets one Fixed line.

### 2. The builder without the Skill tool, and the gate-runner in the foreground

- [ ] Built
- Done when: `slipway run step-check` is green, with `the step brief prints each conventions skill's SKILL.md path, or that it is not found` and `the step builder has no Skill or Agent tool` passing; `slipway report D2.2 --check` passes; `npm ci --prefix site` and then `npm run build --prefix site` are green.
- Records: none
- Paths: `agents/step-builder.md`, `agents/gate-runner.md`, `skills/ship/SKILL.md`, `scripts/lane.mjs`, `scripts/lane.test.mjs`, `scripts/report.mjs`, `scripts/report.test.mjs`, `scripts/components.test.mjs`, `docs/design.md`, `CHANGELOG.md`

What this step changes:
- **The step brief.** In `stepBrief`, `slipway lane --step` prints one line per conventions skill. The line gives the skill's `.claude/skills/<name>/SKILL.md` path relative to the worktree, or says `not found in .claude/skills`. The test that names this behaviour covers both cases.
- **The builder.** `Skill` comes out of the step builder's `tools`. Its orient step now reads each printed `SKILL.md` with Read and names any skill that was not found in its report. `slipway report` already counts those same files, so its count does not change; its tests change only if the agent body's bytes move them.
- **The gate-runner.** It always runs in the foreground, with the Bash tool's longest timeout. It never polls and never starts a background run. A run that the tool cut off is reported as `BLOCKED: timed out`.
- **Ship step 5.** When the gate comes back `BLOCKED: timed out`, the ship gives the operator `slipway run gate` to run themselves. It waits for their result, and that result goes into the evidence comment.
- **The design.** §4.4 and §7 say the builder reads its conventions skills from the paths in its brief and has no Skill tool, so Claude Code's skill listing is not part of its load.
- **Changelog.** `## Unreleased` gets one Changed line.

## Asked at scope

- Builder's skill listing: dropped `Skill` from the step builder, which reads its conventions skills by path. Declined keeping `Skill` and counting the listing in `slipway report`. A conventions skill kept only in a plugin or in user scope can no longer be loaded by the builder.
- Gate-runner: always in the foreground with the longest timeout. A cut-off run is `BLOCKED: timed out`, and the operator then runs the gate. Declined a spike on whether a subagent's background run re-invokes it.
- Plain commands: as proposed. Every skill, agent and plan-template command is one plain command, the new test holds this, and done-whens are plain commands or test names.
- CI: `on` (the config's default). Declined `at-ship` and `off`.
- Release: `patch`, so this ship tags `v0.2.1`. Declined `minor`.
