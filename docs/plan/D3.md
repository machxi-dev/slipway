## Constraints

- Run every command as `slipway run <name>`. A step is one commit with the trailers, plus at most one review-findings commit ([0002](../adr/0002-the-process.md)).
- Plan and scope never commit on the default branch ([0002](../adr/0002-the-process.md)).
- Every skill and agent stays at or under its byte ceiling in `scripts/components.test.mjs` (design §4.1). A step that adds text trims other text to make room. No ceiling rises in this lane.
- The design keeps its section numbers, because `site/scripts/sync.mjs` reads them.
- A config with `release.title` is refused by an older plugin. That is accepted, and the changelog says so. Every other key and default stays as it is.

### 3. The release title, the changelog section, the release notes and the pull request body

- [ ] Built
- Done when: `slipway run step-check` is green, with `release bump renames the changelog's Unreleased heading to the version and date`, `release.title defaults to the tag and fills {version} and {tag}`, `release notes writes the version's changelog section to a file` and `pr-open --plan builds the body from the plan's goal, steps and CI line` passing.
- Records: none
- Paths: `scripts/config.mjs`, `scripts/config.test.mjs`, `scripts/release.mjs`, `scripts/release.test.mjs`, `scripts/forge.mjs`, `scripts/forge.test.mjs`, `scripts/cli.mjs`, `scripts/fixtures/**`, `slipway.config.json`, `templates/slipway.config.json`, `skills/ship/SKILL.md`, `skills/scope/SKILL.md`, `skills/build/SKILL.md`, `site/src/guide/configuration.md`, `docs/design.md`, `CHANGELOG.md`

What this step changes:
- **Config.** `release.title` is optional, takes `{version}` and `{tag}`, and defaults to `{tag}`. This repository sets `"Slipway v{version}"`.
- **Bump.** `slipway release bump` renames `## Unreleased` in a root `CHANGELOG.md`, when the file exists, to `## <version> — <date>`. It lists the changelog among the files it wrote. It refuses a changelog that has no `## Unreleased` heading.
- **Notes.** `slipway release notes [--out <file>]` writes the current version's changelog section and prints the release title.
- **Ship step 8.** The ship uses the printed title and `--notes-file` for `gh release create`. It says it tags the merge commit, not the ship commit.
- **The pull request body.** `slipway forge pr-open --plan <path>` builds the body from the plan's goal, its step titles and its `CI:` line, and replaces `--body-file`. Scope and build use it.
- **Docs.** §4.5 step 8 and the configuration guide name the key.
- **Changelog.** Added and Fixed lines, with a note that a config using `release.title` needs this version.

### 4. Worktree removal from the main checkout, and the default branch brought up to date

- [ ] Built
- Done when: `slipway run step-check` is green, with `worktree remove updates the default branch when the main checkout is on another branch` and `worktree remove updates the default branch with a fast-forward pull when it is checked out` passing.
- Records: none
- Paths: `scripts/worktree.mjs`, `scripts/worktree.test.mjs`, `skills/ship/SKILL.md`, `scripts/components.test.mjs`, `docs/design.md`, `CHANGELOG.md`

What this step changes:
- **The default branch.** `slipway worktree remove D<n>` brings the local default branch up to the remote before it removes anything:
  - `git pull --ff-only` in the main checkout when that checkout has the default branch;
  - `git fetch origin <default>:<default>` when it does not.
- **Ship step 9.** The ship runs `slipway worktree remove D<n>` from the main checkout, with the `git -C` path that `git worktree list` gives, because on Windows a shell inside the worktree keeps the folder. It drops the separate `pull --ff-only`, and the test that listed it changes with it.
- **Docs.** §4.5 step 9 and §14 say the same.
- **Changelog.** One Fixed line.
