# Ship $ARGUMENTS

The design's §4.5, §4.6 and §4.7, and the repository's process record. Nine steps; the operator is stopped once, at step 3. Run `slipway config` for `forge`, `merge` and `release`.

**A fix-forward** at the ship goes to `slipway:step-builder` with this prompt: the worktree, `D<n>`, "ship fix-forward: build no step and tick nothing; fix only this", the failure or the overturned line with its answer, and "commit `fix(<scope>): D<n> ship — <what>` with the template body; no `[skip ci]` unless the lane's `CI:` is `off`; write no decisions line and amend no record or plan: report any decision instead". A decision it reports goes to the operator, and its line is written already marked with the answer.

1. **The lane.** `slipway lane` (with `D<n>` when given) prints the status, `CI:`, branch, plan, decisions file, worktree and steps. Stop unless the worktree exists with the lane's branch checked out; run every command below in it (`cd` there first). A status `shipped` with a `chore(ship): D<n>` commit on the branch is a ship interrupted after step 4: resume at step 5. Otherwise stop unless the status is `in progress` and every step is built; name what is not. `slipway forge comments` should hold a `D<n>.<k> reviewed:` line for every step; a step without one is owed its review: stop and point to `/slipway:build`.
2. **Merge the default branch in**: `git fetch origin` (with a remote), `git merge origin/<default>` (or `<default>`). A conflict in a digest is resolved by `slipway digest`; in the ledger's table, by `slipway ledger generate`; anything else by reading both sides. Commit the merge.
3. **The one stop.** In one message: every open line of the decisions file (`Provisional`, `Owed`) with the step's choice and what overturning costs, and every item of the plan's `## Done when` a machine cannot run (a browser walk, a deployment), as a checklist. Wait for every answer. Then mark each decisions line, editing the line in place: `Ratified YYYY-MM-DD`, `Overturned YYYY-MM-DD, <what replaces it>`, or for an owed one `Paid D<n>.<k>` when this lane paid it, or `Carried YYYY-MM-DD to D<m>` when the operator leaves it to a later row (add it to that row's `ROADMAP.md` entry). An overturned line is fixed forward now, as above.
4. **The ship commit.**
   - `slipway adr accept <n>` for each record the plan's `Records:` line names that is still `proposed`; then `slipway digest`.
   - With a `release` block: `slipway release bump <part>`, the part from the plan's `- Release:` line.
   - `slipway ledger ship D<n> --pr <url>` (the url from `slipway forge pr`; none under `forge: none`) moves the row to `SHIPPED.md` with today's date and marks the plan `shipped`; it prints each file it wrote, and the ship commit takes them all.
   - One changelog line, in the repository's style, where it keeps one.
   - `slipway docs-check` passes; no check runs: step 5's gate is the one proof.
   - Commit by explicit path, `chore(ship): D<n> — <title>`, body naming the decisions marked and the records accepted; end it with `[skip ci]` **only** when `CI: off`. Push.
5. **The gate**, on that commit: `slipway:gate-runner` runs `gate` under the lock. On `BLOCKED: timed out`, give the operator `slipway run gate` and wait; their result goes in step 6's comment, and their run may first wait on the lock the cut-off run holds. Also run the other machine items of the definition of done. A failure in what the lane reaches: fix forward, as above, and rerun the gate. A failure only outside the lane's reach: say so and ask. With `CI: on` or `at-ship`, after the gate has ended: `slipway forge run --sha <head> --wait --log`; red is fixed forward the same way, and the gate runs again on the new head. Never merge without a green gate on the head that merges.
6. **One comment** to a file outside the repository, then `slipway forge comment --body-file <file>`: each command run, its counts and duration, the machine (`node -p "process.platform+' '+process.arch"` and its Node version), and the CI run's result and link, or that the lane ran with `CI: off`.
7. **Merge.** Note the lane head, `git rev-parse HEAD`. `slipway forge ready`, then `slipway forge merge`. Where the permission layer refuses either, give the operator both commands and continue when they say merged. Under `forge: none` the merge is local, `--no-ff`, where the main checkout has the default branch, brought up to origin first and pushed after.
8. **Tag** the merge commit, not the ship commit: `slipway tag D<n> --head <lane head> --pr <url> --title "<title>"`. Under `merge: squash`, first run `git rev-parse origin/<default>` as its own call right after the merge, and pass its hash as `--commit <hash>`, not `--head`. An existing tag stops the ship. A release tag under `forge: github` gets its page: `slipway release notes --out <file>`, outside the repo, prints the title and writes the version's changelog section; then `gh release create <tag> --verify-tag --latest --title "<that title>" --notes-file <file>`, or `--generate-notes` if it finds no changelog.
9. **Clean up.** `cd` to the main checkout (`git worktree list`, first line), since on Windows a shell inside the worktree keeps its folder; then, as the last command, `slipway worktree remove D<n>`, which brings the default branch up to origin first. If git refuses to delete a squash-merged branch as unmerged, or the worktree is held open, say so and leave it to the operator. Report the merge commit, the tag, the gate's counts, the CI run, and the decisions marked. Fewer than two `planned` rows left in the ledger: offer `/slipway:plan`; otherwise `/slipway:scope`.

Never: merge on a red or missing gate; mark a decisions line the operator has not answered; force anything, move a tag, or skip a hook; run the gate in this context.
